## 1 · `ai.truncated` is no longer retryable

**One word, and the reasoning was already ten lines above it.** `client.ts` says of an HTTP 400: *"a 400 means the request is wrong and will be wrong again in thirty seconds. Retrying that only burns the cap."* Truncation is the same shape — **same images, same prompt, same ceiling** — and shipped as `retryable: true`.

**Cost of that word: nine full image payloads for nine identical failures.** Three batches × three attempts.

## 2 · A failed call now reaches the ledger

**The runner's figure is the one that matters: `visitSpend` reported $0.17 while roughly $1.50 had been spent**, against a $2.00 cap that never came close to firing. **~75% of real spend was invisible to the thing bounding it.**

**And the framing is right — this is §2's warning through a second door.** A cap without rates is decoration; **a cap that cannot see failures is decoration during exactly the incident it exists to stop**, because a run failing repeatedly is precisely when spend runs away. The rates were correctly set here and it made no difference.

**What was built:** `ModelCallFailed` now carries a `FailedCallSpend` — model, tier, prompt identity, and the model's **own** reported token usage. The worker writes an `ai_generations` row from it before failing the job.

**Three deliberate boundaries:**

- **Only for calls that reached the model.** Truncation, refusal and an unparseable answer all happen *after* the tokens are consumed. **A 429 or a 500 never reached it, so no row is written** — a zero-cost row there would be the same dishonesty pointing the other way.
- **Usage is read, never estimated.** A failure whose cost is guessed is a different lie from one whose cost is hidden.
- **`abstained` stays false.** Abstaining is the model declining to guess, which is a success. This is a call that produced nothing usable, and the two must not merge — the output column carries `{ failed: true, code, message }` so the row is legible as a cost with no result.

## 3 · The output ceiling is per tier

**`IDENTIFY_MAX_TOKENS = 4096` was sized against the cheap tier.** Measured on the mechanical room: Haiku answered in **2,185 / 2,877 / 1,507** output tokens; Sonnet overran 4,096 on **all three — including the six-photograph batch Haiku finished in 1,507.**

**`ModelConfig` gains `maxOutputTokens`**, from `HOUSESTEADY_{FAST|STRONG}_MAX_OUTPUT_TOKENS`, defaulting to **4,096 fast and 16,384 strong**.

**`IDENTIFY_MAX_TOKENS` survives as the floor**, so a model config that forgets to declare one cannot make the ceiling *smaller* than what already worked. **A ceiling is raised deliberately rather than removed** — it is the cap on a runaway answer, and the next model's verbosity is not knowable from here, which is why it is a variable.

## 5 · Does the object model carry a parent/component relation? — **No.**

**Read at source. `objects` carries:** `id` · `property_id` · `zone_id` · `import_id` · `class_id` · `label` · `confirmed_by` · `confirmed_at` · `actor_id` · `generation_id` · `created_at`.

**No `parent_id`, no `component_of`, no `part_of`.** Objects are **flat within a zone**, and the only relations that exist are `object_media` (evidence) and `object_provenance` (decisions).

**So *systems render, parts surface when they have an age, a horizon, a part number or a service call* is not expressible today, in either direction.** There is no way to say the Geo-Flo circulator belongs to the geothermal heat pump, and therefore no way to render one and fold the other.

**⚑ And it interacts with the duplication finding in a way worth naming before anyone builds it.** Four `well-pressure-tank` proposals for one tank and a parent relation are the *same* missing capability seen twice: **nothing in the pass resolves identity across photographs.** A parent link asks *is A part of B*; deduplication asks *is A the same as B*. **Both need the model to reason about two proposals at once, and it is currently never asked to.** Building the relation without that leaves it hand-populated forever.

**Not built.** The Object/Concern Model is ratified and CLAUDE.md §7 says neither Code session invents changes to it. **This is a v2 question and it now has evidence behind it.**

## 6 · Is there a field recording *where* a piece of text was read from? — **No, and that is the NextEnergy error exactly.**

**`readable` is one string with no source.** The prompt asks for *"anything printed you can actually read on it: **a brand on a fascia, a model on a plate**"* — **it names both surfaces in one sentence and provides one field for them.**

**That is the whole failure.** NextEnergy is a dealer or fascia brand; ClimateMaster is what the data plate says. **Both are legitimately "printed on it", the schema cannot tell them apart, and the label took the wrong one — twice, across two runs.**

> **This is the honesty-label problem inside a single field.** A manufacturer read off the unit's own nameplate is `Observed` at the finest grain the pass has. A name on a sticker beside it is `Observed` too — of the *sticker*. **Collapsing them is the same act as laundering an inference into an observation**, one level down, and doctrine 2 forbids exactly this.

**And there is a second gap underneath it: `readable` never reaches the objects table.** `writeProposedObjects` stores class, label, evidence, actor and generation — **not `readable`, not `whatYouCanSee`, not `basis`.** All three live only inside `ai_generations.output`. So the 32 plate readings the first run produced are **recoverable but not queryable**, and nothing downstream can use them.

**Recommended, and all three are the design session's to rule:**

1. **Split `readable` by surface** — a small closed vocabulary (`nameplate` · `fascia-brand` · `adjacent-sticker` · `handwritten-tag`), so a manufacturer claim can cite the surface it came from. **Amendment 10 §B1's principle — the finest read is authoritative — applied to text rather than to images.**
2. **Promote the readings to their own rows**, so a plate string is a queryable fact with provenance rather than a substring of a JSON blob.
3. **A label may not assert a manufacturer that only a non-nameplate surface supports** — which is a rule the split makes checkable and which nothing can enforce today.
